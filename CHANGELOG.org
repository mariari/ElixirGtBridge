** v0.17.0

*** Features

- Event-sourced module bus :: All BEAM module lifecycle
  (~:recompiled~, ~:source_written~, ~:source_removed~,
  ~:compile_failed~) flows through a single ~EventBroker~ publisher
  → ~/EVENTS~ SSE stream → GT-side ~BeamEventAnnouncer~ with
  per-module + default fan-out.  Subscribers re-render from the
  announcement payload without round-tripping the bridge.

- Hot reload survives self-modification :: ~/EVENTS~ moved to a
  ~cowboy_loop~ handler so the bridge's own recompile doesn't kill
  the connection (previously died every-other save via BEAM's
  two-version code purge).  ~CodeMonitor~ + ~HotReload~ siblings
  excluded from self-save cascade.

- Wrench-driven module creation :: Unresolved Elixir module names
  show a "Create" wrench affordance.  The create-module form
  autocompletes from path-dep applications and writes a starter
  source file routed through ~HotReload~.

- Module coder trash button :: Delete the source file + purge the
  BEAM module from the module coder header.  Broadcasts
  ~:source_removed~ so ~BeamModuleSourceCache~ +
  ~BeamModuleResolution~ drop derived state.

- Compile-failure notifications :: Bordered notification with
  module / function-arity / line / message.  ~Open~ button jumps
  to the failing function in its coder.  Failure recovery splices
  edits into last-known-good source from ~BeamModuleSourceCache~
  so subsequent saves don't corrupt the file.

- Function coder action bar :: ~✓ Save~ (leftmost) + ~✗ Discard~
  (visible only when modified).  Play button saves first if
  modified.  ~Ctrl-Shift-F~ format shortcut.  Play+Inspect is the
  default runner action.

- ~C-m~ / ~C-n~ code navigation :: Jump to the next/previous
  function definition.  Inline ~|>~ expander resolves the target
  function and inlines its source.  Local call-site detection in
  the function expander styler.

- Streaming filter infrastructure :: Function-coder lists filter
  through a streaming model that re-renders incrementally as the
  filter text changes.  Source-tab focus-line scrolling with
  bounds-checking.

- Analysis extracted into focused subsystems :: ~GtBridge.HotReload~,
  ~GtBridge.DepGraph~, ~GtBridge.Mnesia~, ~GtBridge.Supervision~,
  ~GtBridge.Eval.Preamble~, ~GtBridge.Mix~.  Stateless eval pool
  for sessionId-less ~/ENQUEUE~.  Long-lived ~GtBridge.Xref~
  service with non-blocking startup.

- Lepiter documentation :: Pages for Wrench, Hot-Reload Internals,
  Changing Source Code, Creating New Modules, Compile-Failure
  Notifications.  Lepiter snippets get full import + alias
  resolution.

- Elixir ~@attribute~ syntax highlighting :: First-class styling
  rule for module-level attributes.

*** Bug Fixes

- ~Analysis.extract_functions/1~ handles single-expression module
  bodies (previously returned ~[]~ for them)
- ~ModuleEvent~ ~:kind~ typespec includes all four kinds
- ~SseStream.encode/1~ derives fields from the struct so future
  ~ModuleEvent~ additions propagate automatically
- ~BeamEventStreamReaderExamples~ uses ~self assert: a ~~ b~
  (extends ~Object~, not ~TestCase~)
- ~HotReload~ converts ~Kernel.ParallelCompiler~'s ~{:error,
  errors, _}~ verifier returns into ~CompileError~ raises so the
  failure-path notification fires
- ~ElixirFunctionStreamingModel~ drops stale cache entries on
  refresh (previously a nil-printing proxy survived every refresh)
- Self-save cascade no longer kills the SSE plug or
  ~CodeMonitor~ tracer during sibling ~ParallelCompiler~ recompile

*** Internal

- Dedup ST event machinery (~ensureSubscribed:~, ~fanout:~,
  ~payloadValue:from:~) across announcer + cache classes
- Hoist mix-project introspection (~normalize_dep/1~,
  ~path_deps/0~, ~path_dep_apps/0~, ~path_dep_opts/1~) to
  ~GtBridge.Mix~
- ~withoutPrefix: 'Elixir.'~ idiom across 13 call sites
- Drop dead HTTP response payload from ~reload/2~ (event-driven
  flow makes the response unused)

** v0.16.0

*** Features

- Elixir module coder :: Each function is a first-class
  ~GtSourceCoder~ with Elixir syntax highlighting via
  ~ElixirParser~, save/delete/move/run/help action buttons
  following GT's method coder pattern. Functions display in
  source order with multi-clause merging.

- Code browser :: Namespace-grouped module tree with live
  substring filter, function counts, and doc status columns.
  Clicking a module opens its inspector inline with R|P toggle.
  Available as "Code Browser" tab on system and application views.

- System and application analysis :: ~GtBridge.Analysis~ provides
  xref dependency graphs, doc coverage mondrian views, supervision
  tree visualization with worker pool collapsing, and mnesia table
  inspection. ~ElixirSystemAnalysis~ and ~ElixirApplicationAnalysis~
  expose these as inspectable GT views.

- R|P inspector toggle :: Dual-strip Remote/Proxy mode switcher
  on all BEAM types. Remote shows ~<gtBeamView>~ tagged views,
  Proxy shows GT wrapper views (Raw, Print, Meta). Dynamic mode
  registration via ~<gtInspectorMode>~ pragma: atoms show
  Atom/Pid/State tabs, PIDs show Pid/State tabs.

- Spotter integration :: Search BEAM applications and modules
  directly from the global spotter.

- Import-aware completion :: Module's own functions available from
  first keypress in module coders. Aliases resolve for
  dot-completion.

- Lepiter Elixir snippets :: Bottom-of-inspector playground with
  ~self~ bound to the inspected object and its module imported.

*** Bug Fixes

- Fix atom resolve for underscore-prefixed names (~__meta__~ etc.)
  where ~$_ asUppercase = $_~ caused missing ~:~ prefix
- Fix ~attributeAt:~ crash on atom names containing dots

** v0.15.1

*** Features

- ~h/1~ now supports dot-syntax — ~h(Enum.count)~ and
  ~h(Enum.map/2)~ work like in IEx. ~h/1~ is now a macro that
  inspects the AST instead of evaluating the argument

*** Bug Fixes

- Fix alias dot-completion prefix — typing ~ENarwhal.si~ after
  aliasing now returns ~ENarwhal.sign_a_block~ instead of the
  fully-qualified ~Anoma.Node.Examples.ENarwhal.sign_a_block~
- Fix raw view crash on maps with binary keys — ~ByteArray~ map keys
  (e.g. cryptographic signatures) are now serialized as
  ~<<byte1, byte2, ...>>~ instead of dumping raw bytes into the
  expression string, which caused ~SmaCCParserError~

** v0.15.0

*** Features

- ~flush()~ built-in for eval sessions — drains and returns all
  messages received by the eval process, like IEx's ~flush/0~.
  Useful when user code subscribes ~self()~ to event brokers.
  Messages are silently stashed by ~handle_info/2~ until flushed

** v0.14.1

*** Features

- Persistent ~alias~, ~import~, and ~require~ across eval sessions —
  ~Macro.Env~ is now accumulated alongside bindings using

  ~alias Foo.Bar~ then ~Bar.~ completes ~Bar~'s functions)
- Source code view for module atoms — inspecting a module (via ~h(Mod)~
  or a bare atom) shows the source file tab when the module's compile
  path is locally available

*** Bug Fixes

- Parenthesize last expression in notify wrapper — ~alias~, ~import~,
  ~require~, and ~use~ directives no longer fail with
  ~undefined function alias/3~ when evaluated through GT's snippet
  bridge (~setNotifyToInstruction:~ now wraps as
  ~GtBridge.Eval.notify((expr), ...)~)
- Lazily resolve session ID in completion strategy — completion requests
  now reach the correct per-page eval session instead of the default
  session.  The ~sessionId~ getter resolves from ~viewPharoBindings~
  on demand, and ~fetchCompletionsFor:~ goes through the getter
