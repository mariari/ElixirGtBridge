* Changelog
** v0.19.1

*** Bug Fixes

- Cross-module type references resolve :: ~Foo.t()~, ~Range.check()~
  and other type calls get their expander triangle again.  0.19's
  cheap cross-module resolution read ~__info__~, which carries no type
  names (they live in the beam type chunk); it now fetches them via
  ~Code.Typespec.fetch_types/1~.
- Local calls resolve without a context module :: a bare local call,
  ~defp~ included, resolves against the source's own definitions even
  when the coder passes no module name.  0.19 zeroed the local name set
  and fell through to the foreign export path, which hides privates.
- Wrenches land on the right characters :: unknown-module wrench
  triangles no longer drift into identifiers on CR/CRLF buffers.  The
  framework AST is LF-normalised while the buffer may use CR or CRLF,
  so wrench end positions are remapped between the two;
  ~lineStartOffsetsFor:~ now counts real line-ending widths, which
  hardens the call-site loop against CRLF as well.  No re-parse, so the
  styler speedups are kept.
- A new module's Application button resolves :: the button resolves a
  module's app through ~LoadedModules.app_of~ (falling back beam, then
  source location, then the current app) instead of the raw
  ~Application.get_application~, which returns nil for a module absent
  from every frozen app spec.  A brand-new module now lands on its app.
- Module coders complete their own functions :: the Source tab
  completed nothing module-local (its coder has no snippet element and
  no self object, so no imports were ever loaded) and the Functions
  view offered publics only.  The completion strategy now derives the
  eval session from the coder's context module, and the session
  records the module's ~defp~ names for completion to offer alongside
  the imported publics, so both views complete the whole module.
- Default-argument arities expand to their definition :: expanding
  ~foo(a)~ when the def is ~foo(a, b \\ :x)~ showed a red source-less
  stub (the generated head has no def of its own), and an arity still
  being typed (~foo()~ before its arguments) showed nothing.  Function
  entries now carry their default count; the expander and C-m resolve
  a source-less arity to the def that generates it, a mid-edit arity
  to the nearest greater def, and only genuinely source-less exports
  keep their synthesized stub.

** v0.19.0

*** Features

- One TCP transport replaces HTTP :: the bridge now speaks a single
  framed full-duplex socket (~packet: 4~, JSON) that carries evals,
  completion, bindings, session-close, and the event stream in both
  directions.  ~BeamLinkTcpMessageBroker~ owns the socket; the GT
  side connects with ~BeamLinkApplication connectwithServerPort:~ and
  no longer opens a second client port.  The HTTP/SSE transport, its
  supervisor, and the now-unused ~req~ and ~msgpax~ dependencies are
  gone; both listeners start from ~GtBridge.start_listener~.
- Evals return synchronously :: an eval result comes back in the
  reply to the command instead of arriving later on a notify
  callback, so the caller that asked for the value is the one that
  receives it.
- One wire decoder, proxies delivered as values :: a single recursive
  decoder reifies the serializer's wire form in one place.  The
  serializer sanitizes every term (not just some), proxied lists
  materialise in a single call instead of one round-trip per element,
  pids rebuild from the wire rather than being flattened to text, and
  list elements keep their identity when that identity is the point.
  Call sites travel as a relation of values, retiring
  ~call_sites_relation~, and derived facts record what they were
  computed from.
- Completion reads projections, not re-parses :: module and Erlang
  names complete from the ~LoadedModules~ projection (seeded from the
  VM), docs come straight from the Docs chunk instead of
  ~Code.fetch_docs/1~, and the source is only parsed when the cursor
  could actually be inside a struct.

*** Performance

- Coder opens without a full re-parse :: the Functions tab is guarded
  from compiled BEAM metadata instead of re-parsing every function
  (~33 ms~ down to ~1 ms~), so the coder's tabs appear immediately
  instead of after a white flash.
- Function-expander styler is no longer O(n^2) :: precomputed
  line-start offsets and reuse of the framework AST drop two
  redundant re-parses (cold ~369 ms~ down to ~20 ms~).
- Cross-module call sites resolve from exports :: a referenced
  module's call targets come from its compiled export table rather
  than re-parsing its source on every keystroke (cold ~114 ms~ down
  to ~16 ms~).
- Bridge call profiler :: a profiler built on PharoLink's existing
  signals measures per-call cost end to end.

*** Bug Fixes

- Elixir coders keep their own stylers :: the Pharo debugger addon no
  longer installs its stylers on Elixir coders, and the override
  lives in the shared trait so every coder that needs it inherits it.
- A failed call-sites fetch is not cached :: a transient failure no
  longer poisons the cache and blanks the wrenches until the next
  recompile.
- New modules resolve their application :: a brand-new module in a
  path dep is placed in its owning app from its source location, so
  the Application button finds it instead of showing nothing.

** v0.18.0

*** Features

- Multi-module files work through the save pipeline :: a file with
  several modules (siblings, nested ~defmodule~, ~typedstruct
  module:~ children) edits the module you are actually in.  Function
  add/save/move resolve their target through one ~module_scope~
  walker shared with the readers; appending to a
  typedstruct-generated module is a no-op instead of landing in the
  enclosing module.
- Every compiled module refreshes its own caches :: each module
  compiled from a save carries its scoped ~all_functions~ list on
  its ~:recompiled~ event, so sibling and nested modules re-render
  too, not just the file's first module (stale sidebar entries and
  the stuck add-function draft pane both came from this).
- Removed modules are purged, added modules persist :: a save that
  drops a module broadcasts ~:source_removed~ for it (computed from
  the file's previous source, purging code, beam, and projections),
  and a brand-new module's beam is persisted to its app's ebin so it
  survives until the next full compile.
- Loaded-module reconciliation :: ~LoadedModules~ converts
  code-server reality into facts.  Modules born outside the bridge
  (iex ~defmodule~, dynamic codegen, eval snippets) enter the record
  after every eval and at bridge connection; ~full_sync~ also
  retracts modules that no longer exist anywhere.  Fact entry is
  fire-and-forget, so eval bursts cannot starve the event stream.
- Functions list filters :: GT's filter-v2 bar on the Functions tab
  narrows by Kind, Name, and body Substring, case-insensitively,
  with the matches highlighted in place in each function's source.
- Mondrian node colours :: ~Mondrian.node_color/2~ colours graph
  nodes end to end, GT renders the colour with a darker border, and
  clicking a node spawns its object.  (l4e21)
- Inline function coder :: the ~|>~ expander dropdown and the
  Add-function draft embed a real function coder, so completion sees
  the module's imports and aliases; no-source functions render their
  synthesized signature.
- Struct completion in every cursor context :: ~%__MODULE__~,
  ~%File.~ (submodule structs), and ~%@attr~ complete with the ~%~
  prefix instead of crashing the completion request.
- ~pid~ eval binding :: snippets reach their session process through
  the ~pid~ binding (named so the inspector keeps ~self~ for the
  inspected object).
- Function edits recompute ranges from source :: save, move, and
  append splice against the source that was passed in, so cached
  line drift cannot corrupt a file; append locates the module end
  from the parse, not a text scan.
- Types survive source listings :: typedstruct-with-options types
  are located correctly and a save keeps type entries in the
  function browser.
- Module enumeration via projection :: the browser and spotter list
  the live ~LoadedModules~ projection instead of the boot-frozen app
  spec.
- Xref index at bridge startup :: indexing moved off VM boot; the
  test suite waits for readiness instead of racing it.

*** Bug Fixes

- Substring filter highlight agrees with its match (both
  case-insensitive).
- Hot-reload examples run in the test suite; the xref example waits
  on the broker's own recompile fact instead of sleeping.
- The tree is clean under ~mix format --check-formatted~ and ~mix
  dialyzer~ (PLT config now includes ~:mnesia~; a provably dead
  fallback clause removed).

** v0.17.0

*** Features

- Event-sourced module bus :: All BEAM module lifecycle
  (~:recompiled~, ~:source_written~, ~:source_removed~,
  ~:compile_failed~) flows through a single ~EventBroker~ publisher
  → ~/EVENTS~ SSE stream → GT-side ~BeamEventAnnouncer~ with
  per-module + default fan-out.  Subscribers re-render from the
  announcement payload without round-tripping the bridge.

- Hot reload survives self-modification :: ~/EVENTS~ moved to a
  ~cowboy_loop~ handler so the bridge's own recompile doesn't kill
  the connection (previously died every-other save via BEAM's
  two-version code purge).  ~CodeMonitor~ + ~HotReload~ siblings
  excluded from self-save cascade.

- Wrench-driven module creation :: Unresolved Elixir module names
  show a "Create" wrench affordance.  The create-module form
  autocompletes from path-dep applications and writes a starter
  source file routed through ~HotReload~.

- Module coder trash button :: Delete the source file + purge the
  BEAM module from the module coder header.  Broadcasts
  ~:source_removed~ so ~BeamModuleSourceCache~ +
  ~BeamModuleResolution~ drop derived state.

- Compile-failure notifications :: Bordered notification with
  module / function-arity / line / message.  ~Open~ button jumps
  to the failing function in its coder.  Failure recovery splices
  edits into last-known-good source from ~BeamModuleSourceCache~
  so subsequent saves don't corrupt the file.

- Function coder action bar :: ~✓ Save~ (leftmost) + ~✗ Discard~
  (visible only when modified).  Play button saves first if
  modified.  ~Ctrl-Shift-F~ format shortcut.  Play+Inspect is the
  default runner action.

- ~C-m~ / ~C-n~ code navigation :: Jump to the next/previous
  function definition.  Inline ~|>~ expander resolves the target
  function and inlines its source.  Local call-site detection in
  the function expander styler.

- Streaming filter infrastructure :: Function-coder lists filter
  through a streaming model that re-renders incrementally as the
  filter text changes.  Source-tab focus-line scrolling with
  bounds-checking.

- Analysis extracted into focused subsystems :: ~GtBridge.HotReload~,
  ~GtBridge.DepGraph~, ~GtBridge.Mnesia~, ~GtBridge.Supervision~,
  ~GtBridge.Eval.Preamble~, ~GtBridge.Mix~.  Stateless eval pool
  for sessionId-less ~/ENQUEUE~.  Long-lived ~GtBridge.Xref~
  service with non-blocking startup.

- Lepiter documentation :: Pages for Wrench, Hot-Reload Internals,
  Changing Source Code, Creating New Modules, Compile-Failure
  Notifications.  Lepiter snippets get full import + alias
  resolution.

- Elixir ~@attribute~ syntax highlighting :: First-class styling
  rule for module-level attributes.

*** Bug Fixes

- ~Analysis.extract_functions/1~ handles single-expression module
  bodies (previously returned ~[]~ for them)
- ~ModuleEvent~ ~:kind~ typespec includes all four kinds
- ~SseStream.encode/1~ derives fields from the struct so future
  ~ModuleEvent~ additions propagate automatically
- ~BeamEventStreamReaderExamples~ uses ~self assert: a ~~ b~
  (extends ~Object~, not ~TestCase~)
- ~HotReload~ converts ~Kernel.ParallelCompiler~'s ~{:error,
  errors, _}~ verifier returns into ~CompileError~ raises so the
  failure-path notification fires
- ~ElixirFunctionStreamingModel~ drops stale cache entries on
  refresh (previously a nil-printing proxy survived every refresh)
- Self-save cascade no longer kills the SSE plug or
  ~CodeMonitor~ tracer during sibling ~ParallelCompiler~ recompile

*** Internal

- Dedup ST event machinery (~ensureSubscribed:~, ~fanout:~,
  ~payloadValue:from:~) across announcer + cache classes
- Hoist mix-project introspection (~normalize_dep/1~,
  ~path_deps/0~, ~path_dep_apps/0~, ~path_dep_opts/1~) to
  ~GtBridge.Mix~
- ~withoutPrefix: 'Elixir.'~ idiom across 13 call sites
- Drop dead HTTP response payload from ~reload/2~ (event-driven
  flow makes the response unused)

** v0.16.0

*** Features

- Elixir module coder :: Each function is a first-class
  ~GtSourceCoder~ with Elixir syntax highlighting via
  ~ElixirParser~, save/delete/move/run/help action buttons
  following GT's method coder pattern. Functions display in
  source order with multi-clause merging.

- Code browser :: Namespace-grouped module tree with live
  substring filter, function counts, and doc status columns.
  Clicking a module opens its inspector inline with R|P toggle.
  Available as "Code Browser" tab on system and application views.

- System and application analysis :: ~GtBridge.Analysis~ provides
  xref dependency graphs, doc coverage mondrian views, supervision
  tree visualization with worker pool collapsing, and mnesia table
  inspection. ~ElixirSystemAnalysis~ and ~ElixirApplicationAnalysis~
  expose these as inspectable GT views.

- R|P inspector toggle :: Dual-strip Remote/Proxy mode switcher
  on all BEAM types. Remote shows ~<gtBeamView>~ tagged views,
  Proxy shows GT wrapper views (Raw, Print, Meta). Dynamic mode
  registration via ~<gtInspectorMode>~ pragma: atoms show
  Atom/Pid/State tabs, PIDs show Pid/State tabs.

- Spotter integration :: Search BEAM applications and modules
  directly from the global spotter.

- Import-aware completion :: Module's own functions available from
  first keypress in module coders. Aliases resolve for
  dot-completion.

- Lepiter Elixir snippets :: Bottom-of-inspector playground with
  ~self~ bound to the inspected object and its module imported.

*** Bug Fixes

- Fix atom resolve for underscore-prefixed names (~__meta__~ etc.)
  where ~$_ asUppercase = $_~ caused missing ~:~ prefix
- Fix ~attributeAt:~ crash on atom names containing dots
